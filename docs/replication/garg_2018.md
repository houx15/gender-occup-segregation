# Garg et al. 2018 — Fig 2 Replication

This document describes the COHA-based replication of **Figure 2** from Garg, Schiebinger, Jurafsky & Zou (2018), *Word embeddings quantify 100 years of gender and ethnic stereotypes* (PNAS). The replication validates that our COHA → Word2Vec → bias-metric stack reproduces a published baseline before we extend the pipeline with new American data sources.

Paper: <https://doi.org/10.1073/pnas.1720347115>
Garg's published code: `reference/GARG/EmbeddingDynamicStereotypes/` (vendored in this repo for offline access).

---

## Scope

- **Replicates Fig 2 only** — average relative norm distance (RND) of occupations across COHA decades 1910s–1990s, with bootstrap 95% CI ribbon.
- **Out of scope** (deferred):
  - Fig 1 (static contemporary scatter against US Census occupation gender %).
  - Fig 3 (ethnic-bias time series — needs ethnic name lists).
  - Figs 4–6 (adjective heatmap, NYT fine-grained).
  - Wikipedia GloVe / Google News word2vec / SVD COHA contemporary baselines (used by Garg for Figs 1 / 6 / robustness, not Fig 2).

---

## Methodology

### Metric — relative norm distance (Garg Eq. 3)

For each occupation word `w`, with male centroid `c_male` and female centroid `c_female` (averaged from the gender word lists):

```
RND(w) = ||v_w − c_female|| − ||v_w − c_male||
```

Sign convention used by Fig 2: **positive = closer to male, negative = closer to female**. A downward trend over decades = women's occupation bias growing.

Implemented in `scripts/common/metrics.py:relative_norm_distance`. Empty / shape-mismatched inputs raise `ValueError` rather than returning `NaN`.

### Aggregation

For each decade:
1. Compute male and female centroids using `scripts/common/embedding_utils.py:compute_centroid` over the 20-word gender lists.
2. For each of the 76 occupations, compute RND if the occupation is in the model's vocabulary; record `in_vocab=False` otherwise.
3. Aggregate `mean_rnd` across in-vocab occupations and bootstrap a 95% CI via `scripts/common/metrics.py:bootstrap_ci` (1000 resamples, seed 42).
4. Log a coverage warning if fewer than 50% of occupations are in vocab (typical floor for early COHA decades, where rare modern occupation tokens are missing).

Implemented in `scripts/analyze_garg.py`.

### Training parameters

Garg consumed pre-trained vectors from **HistWords** (Hamilton, Leskovec, Jurafsky 2016) — *not* vectors he trained himself. To replicate from scratch, our `config/profiles/coha_garg.yml` pins training to HistWords' COHA SGNS settings:

| Parameter        | Value | Notes |
|------------------|-------|-------|
| `vector_size`    | 300   | HistWords COHA |
| `window`         | 4     | HistWords default |
| `min_count`      | 100   | HistWords COHA threshold (higher than our default 20 to suppress per-decade noise) |
| `sg`             | 1     | Skip-gram (matches SGNS) |
| `negative`       | 15    | Negative sampling |
| `epochs`         | 5     | Default |
| `seed`           | 42    | For reproducibility |
| `coha.ngram_order` | 5   | We build the corpus from COHA 5-grams (set in `config/profiles/coha_garg.yml`). The older `coha.n` key is silently ignored by `build_corpora_coha.py` — use `ngram_order`. |

Do not change these without updating both this document and the profile.

### Word lists

Verbatim copies of Garg's published lists from `reference/GARG/.../data/`:

- `wordlists/en/garg/occupations.txt` — 76 occupations (`occupations1950.txt`).
- `wordlists/en/garg/gender_words.json` — 20 male + 20 female terms (`male_pairs.txt`, `female_pairs.txt`).

## End-to-end run (Princeton Slurm)

Compute nodes have no internet access — run downloads on the login node.

### 1. Get the COHA archive URLs

The free corpusdata.org distribution is email-gated. If a mentor or collaborator already has the archives, the easiest path is a **Dropbox shared link**:

- Take the shared link Dropbox gives you and **append `?dl=1`** to force a direct download (instead of the HTML preview page). Example: `https://www.dropbox.com/scl/fi/.../coha-5-grams.zip?rlkey=...&dl=1`.
- Paste each shared URL (one per archive) into the `coha.source_archive_urls` list in `config/profiles/coha_garg.yml`.
- `scripts/data_prep/download_coha.py` uses `requests.get` and follows redirects, so Dropbox direct-download URLs work without code changes.

If you are downloading directly from corpusdata.org, paste the URLs from the email confirmation page exactly as provided.

### 2. Login node — download + decompress

```bash
ssh <user>@adroit.princeton.edu       # or the cluster of your choice
cd ~/gender-occup-segregation
python -m scripts.data_prep.download_coha --config config/profiles/coha_garg.yml
```

The script auto-skips archives already present and decompresses each `.zip` into `paths.coha_decompressed_dir/<archive_stem>/`.

### 3. Slurm — corpus, train, analyze, plot

```bash
sbatch slurm/full_pipeline_en.slurm config/profiles/coha_garg.yml
```

`run_pipeline.sh` (invoked by the Slurm script) auto-skips stages whose output already exists. Force flags: `--force-corpus`, `--force-train`, `--force-analyze`, `--force-all`.

### 4. Inspect results

After the pipeline finishes:

```
data/results_en_coha_garg/
```

## Acceptance criteria

The replication is considered successful when:

- The trend in `figures_garg/fig2_garg_replication.pdf` is **monotone-ish downward** across 1910s–1990s, matching Garg's Fig 2.
- Per-decade occupation coverage is ≥ 50% from at least the 1930s onward (early decades may be lower — log a warning, do not fail).
- Mean RND values are within an order of magnitude of Garg's published Fig 2 (exact y-values will not match because we re-train on COHA n-grams from scratch with different preprocessing than HistWords).

After the run, append an "Observed vs Garg" section to this doc summarising what matched and any caveats.

## Troubleshooting

- **`download_coha` 404 / 403** — Dropbox links expire or get revoked. Reshare with your mentor and append `?dl=1` again.
- **`min_count` too high → many OOV occupations** — early decades (1810s–1890s) are intrinsically smaller; expect coverage warnings. Do not lower `min_count` below 100 without updating this doc, since it diverges from HistWords.
- **`load_config` rejects the profile** — usually a missing `paths.coha_decompressed_dir` or empty `coha.source_archive_urls`. The validator surfaces both with explicit messages; don't bypass.
- **Models not discovered** — `analyze_garg` looks under `paths.models_dir` for files matching `embedding.model_name_template`. The Garg profile uses `coha_{unit_name}.model` so the file pattern is `coha_1910s.model`, `coha_1920s.model`, etc.
- **`gensim` import error in tests** — local dev environments with broken gensim are tolerated by the test shim in `tests/test_analyze_garg.py`. The Slurm environment has working gensim and runs the real model I/O.

## Updates after first replication run

The first end-to-end run on our trained COHA produced inflated magnitudes
(~0.16 vs Garg's ~0.05–0.07) and an inverted curve direction. Audit of
`reference/GARG/EmbeddingDynamicStereotypes/` revealed three issues; all are
now fixed and reflected in the code and config:

1. **Missing L2 normalization.** Garg's
   `dataset_utilities/normalize_vectors.py` divides every embedding row by its
   L2 norm before any distance is computed in `changes_over_time.py`. Our
   `analyze_garg` now L2-normalizes every fetched vector before centroid +
   distance (`scripts/common/metrics.py:l2_normalize`).
2. **Sign convention.** Garg's `utilities.differences = vec1 - vec2` with
   `group1=male, group2=female` ⇒ "Avg. Women Bias" axis where positive means
   female-leaning. Our `relative_norm_distance` was flipped; now it returns
   `||v_w − c_male|| − ||v_w − c_female||` to match Garg.
3. **Inconsistent occupation set across decades.** Garg's
   `plot_averagebias_over_time_consistentoccupations` restricts every decade's
   mean to the SAME occupations (those in vocab in ALL decades, plus with
   valid census data when overlaid). Set `analysis.consistent_occupations:
   true` to enable this — eliminates spurious cliffs from per-decade vocab
   churn. Already set in `coha_garg.yml` and the histwords profiles.

Fig 2 now also overlays the **average women-occupation % difference** from
the vendored IPUMS census data on a twin y-axis (matching Garg's published
overlay). The CSV lives at
`wordlists/en/garg/occupation_percentages_gender.csv` and is wired in via
`wordlists.occupation_percentages_file`.

## Running on multiple embedding sources

Beyond the trained COHA pipeline (`config/profiles/coha_garg.yml`), Fig 2 can
now be regenerated against the **published HistWords COHA vectors** (Hamilton
et al. 2016 — the same vectors Garg actually consumed). This is the cleanest
sanity check.

### 1. Download

`scripts/data_prep/download_pretrained_embeddings.py` is the one-shot
downloader. With no arguments it fetches every source it knows about,
unzips it, and writes a `MANIFEST.json` next to the downloads with the
resolved `models_dir` for each source — that's the path to plug into the
matching profile.

List supported sources without downloading:

```bash
python -m scripts.data_prep.download_pretrained_embeddings --source=list
```

Available:

| Source key | What it is | Use for |
|---|---|---|
| `histwords_coha_sgns` | HistWords COHA SGNS, per decade | **Fig 2 (paper-canonical)** |
| `histwords_coha_all` | HistWords COHA bundle (SGNS + SVD + PPMI) | Fig 2 SVD robustness |
| `google_ngram_eng_all` | HistWords Google Books "English (All)" SGNS, per decade 1800s–1990s | Garg-WEAT broader-English arm (not US-specific) |
| `google_ngram_eng_fiction_all` | HistWords Google Books "English Fiction" SGNS, per decade | Garg-WEAT fiction-register arm |
| `glove_wiki_gigaword` | GloVe Wikipedia 2014 + Gigaword 5 | Future Fig 1 / single-year baselines |
| `glove_commoncrawl` | GloVe Common Crawl 840B / 300d | Future Fig 1 / single-year baselines |
| `google_news_word2vec` | Google News word2vec via fse HF mirror (gensim split-save, ~3.5 GB) | Future Fig 1 |

> The `google_ngram_eng_*` vectors feed the **per-category** `garg_weat` mode
> (leadership / family / science on a gender-ideation axis), not the single-trend
> `garg` Fig 2 documented here — see
> [`garg_weat_per_category.md`](garg_weat_per_category.md).

Default invocation — fetch + unzip everything:

```bash
python -m scripts.data_prep.download_pretrained_embeddings \
    --target_dir=/scratch/network/yh6580/gender-occup/data/pretrained_embeddings
```

(omit `--target_dir` to use the in-repo default `data/pretrained_embeddings`.)

A single source:

```bash
python -m scripts.data_prep.download_pretrained_embeddings \
    --source=histwords_coha_sgns \
    --target_dir=/scratch/network/yh6580/gender-occup/data/pretrained_embeddings
```

After the run, inspect `MANIFEST.json` for each source's resolved
`models_dir` (the directory the script detected the actual model files
in) and copy that path into the matching `coha_histwords_*.yml` profile.

`google_news_word2vec` ships on Google Drive in the original
`GoogleNews-vectors-negative300.bin.gz` form, which can't be fetched
headlessly. We use the
[`fse/word2vec-google-news-300`](https://huggingface.co/fse/word2vec-google-news-300)
Hugging Face mirror instead: it's the same vectors in gensim
KeyedVectors split-save format (a small `.model` file plus a ~3.35 GB
`.model.vectors.npy` sidecar). The downloader pulls both files
automatically. Load with `gensim.models.KeyedVectors.load("<.model path>")`
— the sidecar is auto-discovered from the same directory.

### 2. Run analyze + visualize against pre-trained vectors

Two new profiles bypass our download/corpus/train stages entirely
(`embedding.format: histwords` triggers this):

- `config/profiles/coha_histwords_sgns.yml` — Fig 2 on HistWords COHA SGNS
- `config/profiles/coha_histwords_svd.yml` — Fig 2 on HistWords COHA SVD

Adjust `paths.models_dir` in each profile to match the resolved path the
downloader recorded in `MANIFEST.json`. The default values point at
`<target>/histwords_coha_sgns/sgns/` and `<target>/histwords_coha_all/svd/`,
which may differ from how Stanford actually packed the zip.

#### One slurm to run them all

```bash
sbatch slurm/fig2_all_sources.slurm
```

Iterates over the default config list (trained COHA + HistWords SGNS +
HistWords SVD) and produces one Fig 2 PNG per source. Configs whose
`models_dir` is missing or empty are skipped with a clear log message —
the run continues so a missing histwords download doesn't block the
trained-COHA figure.

Pass a custom list to scope the run:

```bash
sbatch slurm/fig2_all_sources.slurm \
    config/profiles/coha_histwords_sgns.yml \
    config/profiles/coha_histwords_svd.yml
```

#### One profile at a time (no slurm)

```bash
python -m scripts.analyze_garg --config=config/profiles/coha_histwords_sgns.yml
python -m scripts.visualize main --config=config/profiles/coha_histwords_sgns.yml
```

Output filename and title both include the `embedding_source` from the
profile, so `figures_histwords_sgns/fig2_garg_replication__histwords_sgns.pdf`
sits alongside our trained-COHA
`figures_garg/fig2_garg_replication__trained_coha.pdf` without overwriting.
